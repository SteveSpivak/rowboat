# Plan

## Slice

Establish the cloud project-management surface for `rowboat` before attempting broad code publishing.

## Steps

1. Inspect current GitHub repository settings and confirm issue state.
2. Create a dedicated GitHub Project under `SteveSpivak`.
3. Create a small label set only if the defaults are insufficient.
4. Review the existing `docs/` folders and group the completed local work into a few workstream issues.
5. Create those issues with links back to the relevant local docs.
6. Write a local `review.md` or `project-log.md` documenting what was created remotely.

## Candidate issue buckets

- open-agent-stack rollout and local-first tooling
- desktop runtime hardening and settings entrypoints
- dual-app convergence and workspace inventory
- local Microsoft source ingestion
- cloud publish and repo hygiene

## Risks

- mixing completed proof with aspirational roadmap language
- creating too many low-signal issues
- implying code is already pushed when only tracking surfaces were created

## Mitigations

- use only repo-backed docs as issue input
- keep the first issue set compact
- write an explicit local review note of what was created and what was not yet pushed
